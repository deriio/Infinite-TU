# Форк: ветки и синхронизация

## Ветки
- `main` — чистое зеркало `upstream/main`. Никогда не коммитим.
- `my/main` — интеграция: апстрим + наши правки (по умолчанию в форке).
- `my/<задача>` — рабочие ветки, вливаются в `my/main`.
- `sync/<дата>` — результат синхронизации, не прошедший сборку/тесты (`my/main` не двигается).

Remotes: `upstream` = n1m21n/Infinite (push отключён), `origin` = наш форк.

## Ручная синхронизация
```bash
scripts/fork-sync.sh
```
Коды выхода: 0 — ок; 1 — грязная рабочая копия; 2 — конфликт мержа (список файлов выведен, мерж оставлен открытым); 3 — тесты/сборка красные (создана `sync/<дата>`).

## Конфликты
`rerere` включён (запоминает решения). Разрешать по смыслу, сверяясь с `docs/fork-changes.md`: наши `// fork:` правки сохранять, правки апстрима не терять. Затем `git commit`, пересборка (`docs/build-notes.md`), self-test, `git push origin my/main`. Никаких `--force`.

## Автосинхронизация
Ежедневная запланированная задача (09:00) запускает скрипт; при коде 2 разрешает конфликты, при неоднозначности/красных тестах оставляет `sync/<дата>` и пишет отчёт. Каждый запуск добавляет строку в `docs/sync-log.md`.
